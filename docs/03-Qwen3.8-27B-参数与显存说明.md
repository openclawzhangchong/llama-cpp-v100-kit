## 二、这个模型是什么来头（关键）

| 项目 | 数值 | 说明 |
|---|---|---|
| 参数量 | 27B（270 亿） | 稠密模型 |
| 层数 | 64 层 | 另有 1 层 MTP 推测解码模块，当前 llama.cpp 不支持，会自动忽略 |
| **注意力结构** | **16 层全注意力 + 48 层线性注意力** | **混合架构（Gated DeltaNet），这是重点** |
| 查询头 / KV 头 | 24 / **4** | GQA，KV 本来就省 |
| 头维度 | 256 | |
| 原生上下文 | 262144（256K） | 官方训练上限，无需外推 |

**为什么注意力结构是重点？**

普通的 27B/64 层模型，每一层都要为每个 token 存一份 KV（对话记忆）。这个模型不一样：

- 只有 **16 层**（第 4、8、12……64 层）是标准全注意力，需要存 KV
- 另外 **48 层**改用线性注意力（Gated DeltaNet），只保存一个**固定大小的状态**，不管上下文多长都不增长

结果就是：它的 KV 开销只有同规格普通模型的**四分之一**，所以 256K 上下文在 32GB 卡上才装得下。

## 三、显存到底怎么算的

```
显存 = 权重(15.3GB) + KV 缓存 + 循环状态(0.15GB，固定) + 运行开销(约1.5GB)
```

**KV 缓存只按 16 层算**（不是 64 层）：

每 1 个 token 的开销 = 16层 × 4KV头 × 256维 × 2(K和V) × 精度字节数

| KV 精度 | 每 token | 64K 档 | 128K 档 | 256K 档 |
|---|---|---|---|---|
| f16（原始） | 64 KiB | 4.0GB | 8.0GB | 16.0GB |
| **q8_0** | 34 KiB | 2.1GB | 4.3GB | **8.5GB** |

所以三个档位的总占用：

| 档位 | 权重 | KV | 循环状态 | 开销 | 合计 |
|---|---|---|---|---|---|
| 64K（f16） | 15.3 | 4.0 | 0.15 | 1.5 | **≈21GB** |
| 128K（f16） | 15.3 | 8.0 | 0.15 | 1.5 | **≈25GB** |
| 256K（q8_0） | 15.3 | 8.5 | 0.15 | 1.5 | **≈26GB** |

32GB 装得下，而且都留有余量。

## 四、为什么 256K 档要换成 q8_0 精度？

256K 如果用 f16，KV 要 16GB，总计约 33GB —— 会顶满并溢出 32GB。
换成 q8_0 后只要 8.5GB，总量降到约 26GB，稳稳当当。

代价极小：KV 精度只影响"很久以前的对话细节会不会记模糊"，对回答质量的影响实测可忽略。
64K / 128K 两档不需要这一步，所以保持最高的 f16 精度。

> 这是 llama.cpp 的标准做法，业界通用。

## 五、参数逐个解释

bat 里最关键的一行（记事本右键 → 编辑即可看到）：

```bat
llama-server.exe -m "!MODEL!" -ngl 99 -fa on -c 65536 -ctk f16 -ctv f16 ^
  --jinja --alias Qwen3.8-27B --temp 1.0 --top-p 0.95 --top-k 20 --min-p 0 ^
  --host 127.0.0.1 --port 8080 --path webui
```

| 参数 | 含义 | 要不要动 |
|---|---|---|
| `-m` | 模型文件路径 | 换模型时才改 |
| `-ngl 99` | 放到 GPU 的层数，99=全部上卡 | 不用动 |
| `-fa on` | FlashAttention，省显存又提速，**KV 量化必须开** | 别动 |
| `-c 65536` | 上下文长度。65536=64K，131072=128K，262144=256K | 想自定义改这里 |
| `-ctk` / `-ctv` | K / V 缓存精度（f16 或 q8_0） | 跟着档位自动变 |
| `--jinja` | **必须保留**。启用模型自带的 Jinja 对话模板，否则多轮对话会错乱 | 别动 |
| `--alias Qwen3.8-27B` | API 里显示的模型名 | 随意 |
| `--temp 1.0 --top-p 0.95 --top-k 20 --min-p 0` | Qwen 官方推荐的思考模式采样参数 | 高级用户可调 |
| `--port 8080` | 服务端口，报错端口占用就改 8081 | 按需 |
| `--host 127.0.0.1` | 只允许本机访问；想让同宿舍的人用改成 `0.0.0.0` | 按需 |
| `--path webui` | 用 `D:\llamacpp\webui` 里的简洁界面 | 删掉则用官方界面 |

另外脚本里有一行：

```bat
set GGML_CUDA_PDL=0
```

**必须保留。** V100 对 CUDA 的 PDL（程序化依赖启动）特性支持不完整，不关掉这个检查，启动时会误报 `CUDA error: invalid device function`。

**token 换算**：1 token ≈ 0.7 个汉字。64K ≈ 4.5 万字，128K ≈ 9 万字，256K ≈ 18 万字。

## 八、名词小词典

- **token（词元）**：模型处理文字的最小单位，≈ 0.7 个汉字
- **上下文（`-c`）**：一次能处理的"提问 + 回答 + 文档"总长度
- **KV 缓存**：模型记住历史内容用的显存，全注意力层才有；本模型只有 16 层需要
- **Gated DeltaNet / 线性注意力**：用固定大小的状态代替不断增长的 KV，长上下文的关键
- **GQA**：分组查询注意力，多个查询头共用少量 KV 头（本模型 24 : 4）
- **量化（Q4_K_M）**：压缩参数存储，Q4 ≈ 每参数 4.5bit，体积小、速度快、损失小
- **MTP（Multi-Token Prediction）**：一次预测多个 token 的加速模块，当前 llama.cpp 尚未支持
- **`-ngl`**：放到 GPU 上计算的层数，越大越快
- **TCC 模式**：Tesla 计算卡的专用工作模式，把显卡从"显示设备"变成"纯计算设备"
